# 无线模式 UART 协议

本协议只负责 FPGA 与上位机之间的控制通信。摄像头识别、扫频策略和目标判定均由上位机完成。

## 串口参数

- 波特率：`921600`
- 数据格式：`8-N-1`
- FPGA 系统时钟：`100 MHz`
- 空闲电平：高
- 字节顺序：多字节整数均为小端
- 频率单位：毫赫兹（mHz），例如 `20.4 kHz = 20_400_000`
- 相位单位：一周的无符号 Q16，`0x4000 = 90°`，`0x8000 = 180°`

RTL 使用分数波特率累加器，100 MHz 下会自动交替使用相邻的整数位宽，从而避免固定取 `108` 或 `109` 个时钟带来的长期波特率误差。

## 帧格式

| 字节 | 内容 |
|---:|---|
| 0 | `0xA5` |
| 1 | `0x5A` |
| 2 | 协议版本，固定 `0x01` |
| 3 | 命令 |
| 4 | 序号 `SEQ` |
| 5 | 载荷长度 `LEN`，范围 0～8 |
| 6… | 载荷 |
| 最后 | CRC-8/ATM |

CRC 参数为多项式 `0x07`、初值 `0x00`、不反射、无最终异或；计算范围从版本字节到最后一个载荷字节，不包含同步头和 CRC 本身。

FPGA 对不完整帧设有约 2 ms 超时。版本错误、超长帧、CRC 错误帧均不会执行命令。

## 完整工作流程

1. 保持有线模式，按 KEY4 输入 100 kHz 参考并完成频率校准，等待 LED4 点亮。
2. KEY1 切换到无线模式，LED1 常亮；DAC1先保持中值，DAC2继续输出KEY5当前选择的固定校准频率。
3. 按 KEY2、KEY3 或 KEY4。FPGA 进入 `RECOGNIZE`，仅DAC1开始发送校准后的10 kHz单周期锯齿脉冲，同时向上位机发 `START (0x81)`。
4. 上位机识别后发送 `SET_RANGE (0x10)`，给出允许的扫频范围。
5. 上位机另行发送 `SCAN_BEGIN (0x11)`。只有这条命令会结束锯齿脉冲并进入扫频状态。
6. 上位机循环发送 `SET_FREQUENCY (0x12)`；DAC1生成对应正弦波，DAC2不跟随SCAN变化。
7. 需要调相时发送 `SET_PHASE (0x13)`。频率值和相位值是互相独立保存的，更新其中一个不会清除另一个。也可用 `SET_FREQUENCY_PHASE (0x17)` 原子更新两者。
8. 上位机识别到目标后发送 `DONE (0x14)`。FPGA 保持最终正弦输出，LED4 点亮，直到新一轮 START、ABORT 或退出无线模式。

在步骤3～8的任意时刻按KEY6，会取消当前无线流程并返回步骤2的无线空闲状态。无线模式本身不退出，LED1保持亮，LED2～4熄灭，DAC1立即回到中值码512，DAC2固定测试音继续输出。FPGA同时向上位机发送`ABORTED (0x83)`，上位机应终止本轮摄像头识别、扫频或调相。

无线模式不存在标称 30 MHz 的备用输出。若 100 kHz 校准尚未完成，KEY2/3/4 不会产生 START，DAC1/DAC2 始终保持中值码 512，控制命令返回 `NOT_CALIBRATED`。

锯齿和正弦都使用冻结的 100 kHz 校准频率字。任意正弦频率按下式换算：

```text
wireless_phase_step =
    round(calibrated_100k_phase_step × requested_frequency_mHz
          / 100_000_000)
```

因此所有无线频率继承相同的晶振 ppm 校正，除法只在频率命令或校准字改变时执行一次。

无线模式的DAC通道路由固定为：

```text
DAC1 = 识别锯齿 / SCAN频率 / 相位调整结果
DAC2 = KEY5选择的1 / 20.4 / 50 / 80.3 / 100 kHz固定校准测试音
```

KEY5在有线和无线模式下都只切换DAC2固定测试音，不影响DAC1。

## 上位机发给 FPGA

| 命令 | 值 | LEN | 载荷 |
|---|---:|---:|---|
| `SET_RANGE` | `0x10` | 8 | `min_mHz:u32`，`max_mHz:u32` |
| `SCAN_BEGIN` | `0x11` | 0 | 无；独立的扫频开始信号 |
| `SET_FREQUENCY` | `0x12` | 4 | `frequency_mHz:u32` |
| `SET_PHASE` | `0x13` | 2 | `phase_q16:u16` |
| `DONE` | `0x14` | 0 | 无 |
| `ABORT` | `0x15` | 0 | 无，回到无线空闲状态 |
| `GET_STATUS` | `0x16` | 0 | 无 |
| `SET_FREQUENCY_PHASE` | `0x17` | 6 | `frequency_mHz:u32`，`phase_q16:u16` |

允许的全局频率范围为 1～100 kHz。`SET_FREQUENCY` 和 `SET_FREQUENCY_PHASE` 还必须落在本轮 `SET_RANGE` 给出的范围内。

## FPGA 发给上位机

### ACK `0x80`

长度为 2，载荷为：

| 字节 | 内容 |
|---:|---|
| 0 | 原命令 |
| 1 | 状态码 |

状态码：

| 值 | 名称 | 含义 |
|---:|---|---|
| 0 | `OK` | 已接受 |
| 1 | `BAD_LENGTH` | 长度错误 |
| 2 | `BAD_VALUE` | 数值或频率范围错误 |
| 3 | `WRONG_STATE` | 当前流程状态不允许 |
| 4 | `NOT_WIRELESS` | 尚未进入无线模式 |
| 5 | `UNSUPPORTED` | 未支持的命令 |
| 6 | `NOT_CALIBRATED` | 100 kHz频率校准尚未完成 |

ACK 使用请求中的同一个 `SEQ`。上位机应等到 ACK 后再发送下一条普通命令。

### START `0x81`

长度为 1，由 KEY2/KEY3/KEY4 触发：

| 载荷值 | 按键/图形 |
|---:|---|
| 1 | KEY2 / 直线 |
| 2 | KEY3 / 圆 |
| 3 | KEY4 / 二倍频图形 |

这是 FPGA 主动发送的事件，使用 FPGA 自己递增的事件序号。

### STATUS `0x82`

长度为 8：

| 字节 | 内容 |
|---:|---|
| 0 | 状态：0 空闲，1 识别，2 扫频，3 调相，4 完成 |
| 1 | 当前图形编号 |
| 2 | 标志位 |
| 3 | 上一次状态码 |
| 4～7 | 当前频率，mHz，u32 小端 |

标志位：bit0 无线模式、bit1 范围有效、bit2 频率有效、bit3 锯齿脉冲有效、bit4 正弦有效、bit5 DONE、bit6 校准有效。

### ABORTED `0x83`

长度为1，由无线模式下的KEY6主动触发。载荷为被取消的图形编号，编码与START相同。这是FPGA主动事件，使用FPGA事件序号；它与上位机发送`ABORT (0x15)`后收到的普通ACK不同。

## LED 与提示

所有板载 LED 仍按低有效处理，并且不闪烁：

| LED | 有线模式 | 无线模式 |
|---|---|---|
| LED1 | 灭 | 无线模式常亮 |
| LED2 | 灭 | 识别/锯齿脉冲期间常亮 |
| LED3 | 灭 | 扫频或调相期间常亮 |
| LED4 | 100 kHz 校准完成 | DONE 后常亮 |

RTL内部保留高有效`buzzer_en`状态，但当前顶层端口已按实际工程注释。若后续接有源蜂鸣器，可重新开放该端口；低有效蜂鸣器需要在引脚外层取反。

## 本机工具

仅验证编解码和 CRC，不需要串口：

```powershell
python tools/wireless_uart_host.py --self-test
```

安装串口库并连接板卡，例如 COM5：

```powershell
python -m pip install pyserial
python tools/wireless_uart_host.py COM5
```

交互示例：

```text
range 19500 21000
scan
freq 20400
phase 90
set 20000 180
status
done
```

顶层新增有效端口为 `uart_rx` 和 `uart_tx`；`buzzer_en`当前仅为内部预留信号。工程按要求未添加任何引脚约束。
